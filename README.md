# Ралли вместе

Два человека, одна машина и лесной спецучасток «Сосновый перевал» длиной около 3,4 км. Водитель управляет физической машиной, штурман видит реальное положение экипажа на карте и читает повороты. Интерфейс полностью на русском.

Новый проект находится **в корне репозитория**. Прежняя папка `drift-yard/` сохранена; она не входит в сборку и проверки этой игры.

## Быстрый запуск

Нужен Node.js 22 или новее.

```sh
npm ci
npm run dev
```

Откройте `http://localhost:8787`. Создайте экипаж, скопируйте приглашение и откройте его в **другом браузере / отдельном профиле**. Во второй обычной вкладке тоже можно играть, но сохранённый resume token предназначен для одного участника: дублирование вкладки может перенести `sessionStorage` и восстановить ту же роль.

Включите микрофоны явным нажатием кнопки. Оба игрока нажимают «Я готов», организатор — «На старт». Микрофон не является условием готовности. Кнопка «Повторить голос» запускает новое согласование соединения.

Для горячей перезагрузки UI: оставьте Wrangler запущенным и во втором терминале выполните `npm run dev:ui`. Vite проксирует `/api`, включая WebSocket, в Wrangler. Приглашения будут использовать адрес открытого Vite.

### Планшет в одной локальной сети

На компьютере запускайте `npm run dev` и откройте **на обоих устройствах** `http://<LAN-IP-компьютера>:8787`. Разрешите входящие подключения к этому порту в локальном межсетевом экране. Создавайте приглашение именно с этого адреса: `localhost` планшета — сам планшет. По обычному LAN HTTP работают игра и команды, но большинство браузеров запрещает микрофон. Для голоса используйте публичный HTTPS `workers.dev` после публикации либо собственный доверенный HTTPS в сети. Обход защиты браузера не требуется.

## Управление

- W / ↑ — газ; S / ↓ — тормоз. После остановки удерживайте тормоз 0,7 секунды для заднего хода.
- A/D или ←/→ — руль; пробел — ручной тормоз.
- R — возврат к последней контрольной точке, +5 секунд; повтор не чаще раза в 5 секунд.
- C — камера за машиной / над капотом; Esc — общая пауза.
- Стандартный геймпад: левый стик, RT/LT, A — ручник, Y — камера. Поддержка аппаратных рулей зависит от браузера и не обещается.
- На сенсорном экране есть педали и руль-кнопки.
- Штурман: обзор / слежение, масштаб, перетаскивание карты, север / курс вверх, ручной просмотр заметок и возврат к автоматическим. 1 — очень крутой поворот, 6 — пологий. Команды «Тормози», «Лево», «Право» идут через сервер.

В настройках раздельно регулируются звук игры и голос, отключается тряска. Звуки двигателя, гравия, отсчёта и удара синтезируются; записи и внешние звуковые ресурсы не нужны.

## Проверки

```sh
npm test                 # модель, ICE-очередь, реальная физика, полный физический проезд
npm run build            # TypeScript + production-сборка Vite
npm run preview          # собранная игра и настоящий Worker локально
# В другом терминале:
npm run test:integration # две независимые WebSocket-сессии, весь цикл
npm run test:browser     # Chromium: два профиля, интерфейс, физика, карта, WebRTC
npx wrangler deploy --dry-run
```

Браузерный тест по умолчанию использует `/usr/bin/chromium`. Для Playwright-браузера: `npx playwright install chromium`, затем `CHROMIUM_PATH=playwright npm run test:browser`. Для другой установленной версии задайте путь через `CHROMIUM_PATH`.

По умолчанию тест требует **реальных входящих RTP-аудиопакетов в обе стороны** от синтетических микрофонов. В управляемой среде с политикой `WebRtcIPHandling=disable_non_proxied_udp` без TURN этот тест невозможен. Только для такой среды предусмотрен явный `ALLOW_BLOCKED_WEBRTC=1`: проверяются SDP, сообщение о невозможности соединения, mute и продолжение игры; тест печатает ограничение и **не объявляет аудио проверенным**. В CI это исключение не включено.

`TEST_ORIGIN=https://реальный-адрес` позволяет запускать сетевой тест против опубликованного сервера. Он создаёт одну временную комнату и закрывает её в конце. Сетевой тест финиша отправляет валидируемые протокольные координаты; это не замена тесту физики. Отдельный `stage.test.ts` проходит весь реальный Rapier-мир тестовым регулятором руля/педалей, без перестановки машины; он не включён в игру как автопилот.

## Архитектура и восстановление

- **Vite + TypeScript + Three.js + Rapier**. Четыре raycast-колеса, подвеска, двигатель, тормоза, боковое сцепление шин, гравий/трава, сопротивление скорости. Низкое шасси, ограниченное скоростью руление, физические барьеры. Фиксированный шаг 1/60 с, не более шести подшагов; длинная остановка кадра или скрытие вкладки ставит заезд на паузу.
- `shared/track.ts` — единая сплайн-трасса с подъёмом до 93 м, спуском, шпилькой и гребнями. Из неё получаются поверхность и коллизии дороги, карта, заметки и упорядоченные КТ. Проекция ограничена окном прогресса, поэтому соседняя ветвь шпильки не переносит экипаж вперёд.
- **Один SQLite Durable Object на комнату**: ровно две роли, согласованная смена, readiness, отсчёт, пауза, штрафы, КТ, финиш и рекорд. Короткий случайный восьмизначный код устойчиво разрешается через `idFromName`; инициализация атомарно отказывает при коллизии. Маленький tombstone не допускает повторного использования истёкшего кода.
- Физику считает водитель. Он отправляет снимки примерно 15 раз/с. Сервер проверяет роль, эпоху, последовательность, диапазоны, перемещение, маршрут; сам вычисляет прогресс, КТ, время и финиш. Штурман интерполирует **полученные** координаты. Это кооперативный прототип, не соревновательный античит.
- `acceptWebSocket`, `serializeAttachment` и обработчики Hibernation API сохраняют идентичность сокета, последовательность и последний принятый снимок во время гибернации. Основное состояние сохраняется при изменении жизненного цикла и КТ, **не на каждом кадре**. В объекте нет постоянно работающей симуляции или `setInterval`; короткие alarms обслуживают отсчёт, тайм-ауты и уборку.
- Heartbeat 10 с; умерший клиент определяется не позднее примерно 70 с при отсутствии нормального события закрытия. Гоночный клиент локально замораживается при обнаружении потери связи. Разрыв ставит общую паузу, токен восстанавливает роль; продолжение требует двух подтверждений. После 2 минут паузы комната возвращается в лобби. Сама комната живёт максимум 4 часа, пустая покинутая комната закрывается сразу, полностью отключённое лобби — через 10 минут.
- При полном перезапуске процесса последнее состояние восстанавливается из SQLite, но кадры после последнего сохранённого события могут быть потеряны. При обычной гибернации последний кадр берётся из attachment сокета. Истёкшие комнаты не восстанавливаются.
- Секретный UUID-токен хранится в `sessionStorage`, отправляется первым сообщением WebSocket и в заголовке авторизованного ICE API. Он не входит в URL приглашения, общую комнату или журнал приложения. Сервер ограничивает размеры, сообщения в секунду, создание комнат и попытки входа. Rate Limit binding — распределённая защита от частых запросов, а не строгая глобальная квота.
- Все `/api/*` выполняются Worker до Static Assets, поэтому SPA fallback не поглощает API/WS. В production один HTTPS origin обслуживает приложение, комнаты, WebSocket и сигналинг. Отдельный Node.js сервер и GitHub Pages не нужны.

## Голос: STUN и TURN

Native WebRTC: инициатор — водитель; SDP/ICE идут только второму участнику комнаты. ICE, полученный до remote description, ожидает в очереди. Повторное включение перезапускает переговоры, выход останавливает дорожки и соединение. Есть индикатор входа, mute, повтор подключения, явное разрешение autoplay. Аудио **не записывается**.

Без TURN голос может не соединиться между NAT, мобильными и корпоративными сетями. Успешный WebSocket и даже SDP не доказывают передачу голоса. При отказе остаются карта, машина и быстрые команды. Универсальная связь без реального TURN не обещается.

Для локальной настройки скопируйте `.env.example` в `.dev.vars`. Для production открытые `STUN_URLS`, `TURN_URLS`, `VOICE_RELAY_ONLY` задаются в `wrangler.jsonc`; несколько адресов разделяются запятыми.

Предпочтительный TURN — существующий сервис, поддерживающий TURN REST, например собственный coturn с `use-auth-secret`, `static-auth-secret`, корректными `realm`, внешним адресом, TLS и открытым relay-диапазоном. Его общий секрет установите только на сервере:

```sh
npx wrangler secret put TURN_SECRET
```

Worker выдаёт авторизованному участнику HMAC-SHA1 credential с временем жизни 1 час. Долгоживущий shared secret не передаётся браузеру. Если провайдер требует статическую учётную запись, `TURN_USERNAME` / `TURN_CREDENTIAL` поддержаны как серверные secrets только для временного теста; такой выданный клиенту credential по определению виден участнику. Для публичного сервиса используйте короткоживущую схему.

`VOICE_RELAY_ONLY="true"` включает проверку только relay-кандидатов. Делайте это лишь с действующим TURN; без него голос ожидаемо не соединится. Покупка TURN, платные пробные периоды и платные планы не требуются для сборки и не включены автоматически.

## Бесплатная публикация в Cloudflare

Основной путь: **GitHub Actions → Workers Free + Static Assets + SQLite Durable Objects → HTTPS workers.dev**. Домен покупать не надо. `wrangler.jsonc` содержит binding и миграцию `new_sqlite_classes`.

Один раз владелец подключает аккаунт:

1. В Cloudflare зарегистрируйтесь/войдите, оставьте **Workers Free**, выберите доступный поддомен `workers.dev` в Workers & Pages. Не включайте платный план.
2. Создайте пользовательский API token только для выбранного аккаунта: **Account → Workers Scripts → Edit**, **Account → Account Settings → Read**. Не выдавайте доступ к DNS или всем аккаунтам. Скопируйте Account ID.
3. В GitHub откройте **i7885784-lang/gonki → Settings → Secrets and variables → Actions**. Создайте repository secrets `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Не отправляйте значения в чат и не коммитьте их.
4. Откройте **Actions → Проверка и публикация → Run workflow**, ветка `main`. После успешных проверок Wrangler опубликует Worker; адрес появится в итогах задания. Следующие push в `main` делают это автоматически.

Workflow проверяет сборку, модель, физику, два WebSocket-клиента и два браузера до публикации. PR использует `pull_request`, не `pull_request_target`, и не получает production secrets. Deploy запускается только для `main` после успешного check. После deploy адрес извлекается из реального вывода Wrangler, и against HTTPS выполняется тот же тест двух клиентов. При отсутствии секретов job честно завершается сообщением о неподключённом аккаунте.

Если репозиторий закрытый, GitHub Actions расходует бесплатные минуты аккаунта; оставьте spending limit 0. Для открытого репозитория стандартные GitHub-hosted runner доступны бесплатно. Исчерпание бесплатных минут задерживает публикацию; это не повод включать оплату.

Для ручного локального деплоя с уже настроенным доступом: `npm run deploy`. Команда сама собирает frontend и сохраняет фактический URL в `work/deploy-url.txt`. Не используйте `wrangler dev` как публичный production-сервер.

**Откат:** `git revert <неудачный-коммит>` и обычный push в `main` повторно публикуют проверенную версию. Для срочного отката к сохранённой версии Worker — `npx wrangler rollback <version-id>` с настроенным доступом. Откат кода не откатывает данные Durable Objects; не удаляйте миграции и namespaces.

### Ограничения нулевого бюджета

Проверено по официальной документации 13 октября 2026 года:

- Workers Free: 100 000 динамических запросов в сутки, лимит CPU на вызов; статические assets имеют отдельное бесплатное обслуживание.
- SQLite Durable Objects Free: 100 000 расчётных requests/сутки, 13 000 GB-s/сутки, 5 млн прочитанных и 100 000 записанных строк/сутки, 5 GB суммарного хранения. Входящие WS-сообщения учитываются с коэффициентом 20:1 для request billing; исходящие не тарифицируются как requests. `setAlarm` расходует запись.
- Free при превышении квот прекращает соответствующие операции до восстановления лимита; не включает платное расширение сам по себе. Бесплатный хостинг не означает бесконечное число экипажей или гарантированную доступность. Активные заезды, alarms и heartbeat расходуют лимиты, несмотря на гибернацию между событиями.

Источники: [лимиты Workers](https://developers.cloudflare.com/workers/platform/limits/), [Static Assets](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [Durable Objects Free и SQLite](https://developers.cloudflare.com/durable-objects/platform/pricing/).

## Границы прототипа

Один этап, одна машина, упрощённая графика. Настоящий геймпад, iPad Safari, мобильные операторы, TURN relay и человеческая разборчивость голоса требуют проверки на физических устройствах. WebGL 2 обязателен водителю; карта штурмана — обычный 2D canvas. Потеря вкладки, разрешений, квоты или сети отображается явно. Публичная публикация и межсетевой голос считаются подтверждёнными только после соответствующих проверок, а не по факту успешной сборки.
