# Проверка прототипа «Ралли вместе»

Дата: 14 октября 2026 года.

Проверенный код: `d5750fe`. [Запуск GitHub Actions](https://github.com/i7885784-lang/gonki/actions/runs/38523999270): задание `check` — успешно; `deploy` остановлено из-за отсутствующего подключения Cloudflare.

## Подтверждено в рабочей среде

- Зависимости установлены; `npm run check` завершился успешно: **11 тестов**, TypeScript и production-сборка Vite.
- `wrangler deploy --dry-run` успешно упаковал Worker, Static Assets, SQLite Durable Object и два rate-limit binding. Это **не публикация**.
- Настоящий Wrangler-сервер запущен на порту 8787.
- `npm run test:integration`: две отдельные WebSocket-сессии, назначение ролей, запрет третьего игрока, неизвестный/неверный код, согласованная смена ролей, готовность и общий отсчёт. Проверены запрет старта штурманом, запрет его координат, передача снимков водителя, запрет телепорта, быстрые команды, штраф +5 с без повторного начисления, SDP-сигналинг, разрыв/возврат по токену, два подтверждения продолжения, последовательность всех 27 КТ, одинаковый результат, повторный заезд и закрытие покинутой комнаты.
- `ALLOW_BLOCKED_WEBRTC=1 npm run test:browser`: два независимых профиля Chromium; desktop водитель и сенсорный tablet штурман. Приглашение открывает реальную комнату; клавиатура разгоняет физическую машину, её скорость и координаты передаются штурману. Проверены команды, возврат на трассу, пауза, перезагрузка вкладки штурмана и продолжение, выход, запрет микрофона настоящим browser permission и возможность готовности без него. Критических ошибок JavaScript нет. Просмотрены снимки главной страницы, лобби, водителя и карты в портретной/альбомной ориентации.
- Отдельный физический тест использует только руль/газ/тормоз в Rapier. Все 3 413,6 м пройдены за **208,1 секунды**, максимальное отклонение от оси около **2,04 м** при полуширине дороги 6 м. Это тестовый регулятор, не человеческий плейтест и не игровая функция автопилота.
- Проверены серверная модель, отбрасывание устаревших снимков, последовательность КТ, ICE-очередь до SDP, остановка аудиодорожек. Модульные проверки восстановления DO подтверждают чтение свежего socket attachment при гибернации и паузу при полном рестарте без сокетов. Принудительная гибернация в production Cloudflare ещё не проверена.

## Подтверждено в GitHub Actions

На Ubuntu с полноценным Chromium успешно прошли все 11 тестов, TypeScript, production-сборка, полный сценарий двух WebSocket-клиентов, сценарий двух независимых браузерных профилей и упаковка Worker. Браузерный тест подтвердил **входящие RTP-аудиопакеты в обе стороны** от синтетических микрофонов через настоящий WebRTC, отключение/включение дорожки и отказ в разрешении микрофона. Исключение `ALLOW_BLOCKED_WEBRTC` в CI не включалось.

Для стабильной проверки маршрута тест ожидает получение каждого снимка вторым клиентом; серверная проверка последовательности контрольных точек сохранена. Проверка аудио опрашивает реальные `RTCPeerConnection.getStats()`, а не только состояние интерфейса или SDP.

## Голос — точная граница проверки

В двух браузерах успешно обменялись настоящими offer/answer; работают включение синтетического микрофона, mute и сообщения об ошибках. ICE-очередь отдельно проверена тестом.

У установленного управляемого Chromium политика `WebRtcIPHandling=disable_non_proxied_udp`: ICE gathering завершается без доступных кандидатов. TURN-учётных данных нет. Поэтому в этой рабочей среде двусторонний аудиотранспорт не подтверждён; он отдельно подтверждён в GitHub Actions, как описано выше. **Человеческие микрофоны, разные сети и relay-only пока не проверены**. Политика не изменялась и не обходилась. Исключение теста явно печатает этот статус; обычный browser test и CI требуют входящих RTP-пакетов в обе стороны.

## Публикация и доступы

GitHub-репозиторий доступен для чтения и записи, публичный. Cloudflare в среде не авторизован (`wrangler whoami`). Задание `deploy` в указанном запуске остановилось на проверке переменных: отсутствует один или оба секрета `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`. Wrangler публикации не запускался, публичного HTTPS URL пока нет. Значения секретов не извлекались и не выводились.

В `.github/workflows/deploy.yml` настроен путь push main → проверки → Wrangler → проверка публичной комнаты. Для подключения аккаунта достаточно установить в GitHub repository secrets `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` и запустить workflow. Точная инструкция и минимальные права приведены в README. Платные планы и сервисы не подключались.
